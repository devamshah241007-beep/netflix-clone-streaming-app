## 2025-02-15 - [CRITICAL] Prevent Hardcoded JWT Secret Fallback
**Vulnerability:** The application used a hardcoded string ('your_jwt_secret_change_this') as a fallback for `JWT_SECRET` in both authentication middleware and routes. If the `JWT_SECRET` environment variable wasn't set, attackers could forge valid JWTs.
**Learning:** Hardcoded default secrets are a severe vulnerability because they are committed to version control and publicly known. Generating random fallback keys on startup introduces a separate vulnerability where active sessions are invalidated upon server restart and might cause load balancing issues or race conditions with imports.
**Prevention:** Always enforce a fail-fast startup. If a critical security parameter like a cryptographic key is missing, throw an immediate `Error` preventing the app from starting up rather than silently degrading into an insecure or transiently-secure state.

## 2024-10-26 - NoSQL Injection and ReDoS via Express req.query
**Vulnerability:** Unvalidated optional `req.query` parameters were passed directly into Mongoose queries and `$regex` operators in `routes/content.js`. This exposed the application to NoSQL injection (by passing objects instead of strings) and ReDoS (by passing unescaped regex special characters).
**Learning:** Express implicitly parses query string parameters as objects if they are formatted like `?search[$ne]=test`. When these objects are directly mapped to Mongoose query objects, it allows attackers to inject query operators like `$ne`, `$gt`, etc. Additionally, passing user input directly into `$regex` without escaping can cause catastrophic backtracking if the user supplies complex regex patterns.
**Prevention:** Always validate that `req.query` parameters are explicitly of type `string` before adding them to Mongoose queries. Furthermore, escape any user input strings before using them in `$regex` operations using `.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`.
