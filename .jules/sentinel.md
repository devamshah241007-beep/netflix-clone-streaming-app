## 2025-02-15 - [CRITICAL] Prevent Hardcoded JWT Secret Fallback
**Vulnerability:** The application used a hardcoded string ('your_jwt_secret_change_this') as a fallback for `JWT_SECRET` in both authentication middleware and routes. If the `JWT_SECRET` environment variable wasn't set, attackers could forge valid JWTs.
**Learning:** Hardcoded default secrets are a severe vulnerability because they are committed to version control and publicly known. Generating random fallback keys on startup introduces a separate vulnerability where active sessions are invalidated upon server restart and might cause load balancing issues or race conditions with imports.
**Prevention:** Always enforce a fail-fast startup. If a critical security parameter like a cryptographic key is missing, throw an immediate `Error` preventing the app from starting up rather than silently degrading into an insecure or transiently-secure state.

## 2025-02-23 - [CRITICAL] Prevent NoSQL Operator Injection via req.query
**Vulnerability:** Express `req.query` parameters were passed directly into Mongoose queries (e.g., `req.query.type`, `req.query.genre`, `req.query.search`). This allows attackers to send nested objects via query parameters like `?type[$ne]=movie`, which Express parses as an object `{ $ne: 'movie' }`. When passed to Mongoose, this object acts as a NoSQL query operator, leading to data exposure, bypasses, or ReDoS in regex operations.
**Learning:** Never trust the type of data coming from `req.query` or `req.body` in Express. Because query strings like `key[subkey]=value` are parsed into objects by default, passing them blindly to a MongoDB driver or Mongoose can result in severe injection vulnerabilities.
**Prevention:** Always explicitly validate that parameters are of the expected type (e.g., `typeof req.query.param === 'string'`) before using them in database queries, or convert them explicitly to strings.
