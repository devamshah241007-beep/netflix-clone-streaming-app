## 2025-02-15 - [CRITICAL] Prevent Hardcoded JWT Secret Fallback
**Vulnerability:** The application used a hardcoded string ('your_jwt_secret_change_this') as a fallback for `JWT_SECRET` in both authentication middleware and routes. If the `JWT_SECRET` environment variable wasn't set, attackers could forge valid JWTs.
**Learning:** Hardcoded default secrets are a severe vulnerability because they are committed to version control and publicly known. Generating random fallback keys on startup introduces a separate vulnerability where active sessions are invalidated upon server restart and might cause load balancing issues or race conditions with imports.
**Prevention:** Always enforce a fail-fast startup. If a critical security parameter like a cryptographic key is missing, throw an immediate `Error` preventing the app from starting up rather than silently degrading into an insecure or transiently-secure state.

## 2026-09-23 - [CRITICAL] Prevent NoSQL Operator Injection and ReDoS in Query Parameters
**Vulnerability:** The application passed `req.query` parameters directly into MongoDB queries and `$regex` operators in `routes/content.js`. An attacker could pass objects (e.g., `?type[$ne]=movie`) to manipulate the query logic (NoSQL Injection), or supply complex unescaped regex strings (e.g., `?search=^(a+)+$`) to cause a Regular Expression Denial of Service (ReDoS).
**Learning:** Express `req.query` values can be parsed as objects or arrays instead of strings depending on the query string format. If these are passed directly to Mongoose, it exposes the application to NoSQL operator injection. Furthermore, unsanitized user input in `$regex` operations can easily lead to severe performance degradation.
**Prevention:** Always explicitly validate that Express `req.query` parameters are strings (`typeof param === 'string'`) before using them in database queries. Additionally, always escape regex special characters (`param.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`) when placing user input inside a `$regex` operator.
