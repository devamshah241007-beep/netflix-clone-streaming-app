## 2025-02-15 - [CRITICAL] Prevent Hardcoded JWT Secret Fallback
**Vulnerability:** The application used a hardcoded string ('your_jwt_secret_change_this') as a fallback for `JWT_SECRET` in both authentication middleware and routes. If the `JWT_SECRET` environment variable wasn't set, attackers could forge valid JWTs.
**Learning:** Hardcoded default secrets are a severe vulnerability because they are committed to version control and publicly known. Generating random fallback keys on startup introduces a separate vulnerability where active sessions are invalidated upon server restart and might cause load balancing issues or race conditions with imports.
**Prevention:** Always enforce a fail-fast startup. If a critical security parameter like a cryptographic key is missing, throw an immediate `Error` preventing the app from starting up rather than silently degrading into an insecure or transiently-secure state.

## 2025-02-15 - [HIGH] Prevent NoSQL Operator Injection and ReDoS via req.query
**Vulnerability:** Express `req.query` automatically parses arrays and objects from the query string (e.g. `?search[$ne]=foo`). When these parameters are passed directly into Mongoose queries, it allows NoSQL operator injection. Furthermore, if an attacker provides a crafted string to a MongoDB `$regex` operator without escaping, they can cause a Regular Expression Denial of Service (ReDoS).
**Learning:** Never trust `req.query` parameters to be strings. The Express query parser creates nested objects when brackets are used. Mongoose implicitly accepts these objects, allowing attackers to use operators like `$ne`, `$gt`, or `$regex` to bypass logic or extract unauthorized data.
**Prevention:** Always explicitly validate that `req.query` parameters used in database queries are strings (e.g., using `typeof param === 'string'`). When using `$regex` with user input, the input must additionally have regex special characters escaped.
